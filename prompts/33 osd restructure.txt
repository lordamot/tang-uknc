Done. The OSD is restructured, the FPGA has a switch for every add-on, and both binaries in bin/ are rebuilt. It is built, linted, simulated, host-tested and timed. Nothing has run on a board, and nothing is committed.

The repository
- VERSION ("2.0.0 alpha"), an empty CHANGELOG.md, LICENCE.md with the MIT text in English and Russian.
- mnano/CMakeLists.txt reads VERSION into UKNC_VERSION; the main caption shows it at the right.

The FPGA (tang/src)
- sysctrl.v: letters b (beeper), 1 2 3 (AYs), c (Covox mode), f (FDD controller), e (HDD controller), u (mouse), t (RTC); p q r s replace P for the four write protections; a new SYS command 6 returns the clock, snapshotted at the command byte.
- aberrant.v, covox.v, vp1-128fdd.v, kakave.v take an enable per device. Off means no acknowledge, so the address is a bus timeout as on a machine without the board; an AY that is off is also held in reset and masked out of the sum.
- vp1_120.v brings port A of the printer port out; top.v mixes it as the second Covox when c says Port 177100 LPT or Both, gates the beeper out of the mix, ANDs the HDD switch into the cartridge's hdd_present, and exports the clock.
- Color RGB/BGR was swapping red and green. It swaps red and blue now, which is what the label says.
- The first layout failed the timing gate on the weekday arithmetic into the read-back snapshot; a register in kakave.v fixed it. Final: 0 setup, 0 hold, logic 52 percent, BSRAM 66 percent.

The firmware (mnano)
- menu.c: main / Hardware / Aberrant / FDD controller / HDD controller / RTC clock / Misc, About as a scrolling text page, Save settings on the main form. The main form is built at run time so HDD0 appears only with the controller on. A form returns to the entry that opened it, found by form number, so nothing needs renumbering any more. Cursor left and right step a value either way. The RTC form's last line reads the core's clock once a second.
- One label changed against the request: "HDD image format" beside "Inversed" does not fit 128 pixels, so it is "Image format" inside the HDD controller form.
- make menu-test walks every form on the host and writes each of the 23 screens as a PNG under build/menu; that is how the layout was checked.

What was checked
- make lint, ab-test, covox-test, kakave-test and the new hwen-test all pass; each switches its device off and on.
- make sim boots to the CPU release with the new defaults, reads the clock back right, checks 200k pixels of the RGB/BGR swap, and sees the printer-port byte reach the mixer at modes 2 and 3 and not at 1. The one read-after-write miss it reports is the known SDRAM-model artefact and shows on the unmodified tree too.
- make fw builds; make bitstream passes the gate.

Worth knowing before flashing
- The defaults are a plain machine with the three AYs: Covox, mouse, RTC and HDD all Off, and HDD0 hidden. A saved uknc.ini from before keeps its volume and clock; the old P line is ignored.
- The printer-port DAC is mixed uninverted, like the one at 0177372, for the reason in covox.v.
- The playing of sound through the LPT port has been checked in simulation only; nothing has been heard.
