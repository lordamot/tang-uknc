fix the fdd4.v ind bug in tang-uknc too

****

Fixed, built and through the timing gate. Not run on a board, and nothing is committed yet: the repo's rules say to ask first.

The bug. fdd4.v made the index bit, status bit 15, as (word_sectr >= 1 || word_sectr <= 4) && motor. That is true for every word, so the bit sat at 1 while the motor ran. Swapping || for && would not have fixed it either: word_sectr counts words inside a sector, so it would pulse ten times a revolution.

The fix. The new line is ind = no_sec == 0 && word_sectr < 75 && motor. The index is now high once a revolution, for the first 75 words (150 bytes) of the track. That is UKNCBTL's FLOPPY_INDEXLENGTH; kakave uses 50 words.

Whether it matters to the ROM: it doesn't. I disassembled the driver in uknc_rom.bin, 0131660-0134520. Its status tests are TSTB (TR), BIT #1 (TR0) and BIT #40000 (CRC); nothing reads bit 15. So reading and writing through the ROM is unchanged. Only software that reads the index itself sees a difference: formatters (the ROM's error 14 is an index-line error during formatting), copiers, and loaders with their own disk code.

Checked:
- make lint: the same warnings as before, five lines further down.
- make fdd-test: passes. Two testbench changes:
  - ind is out of the old-versus-new comparison, because the old module's ind was the bug.
  - A new phase checks the index directly: two pulses in 2.2 revolutions, each rising at sector 0 word 0, 75x1600 clocks long, 3124x1600 clocks apart, and low with the motor off.
- make bitstream: built, timing gate ok, 0 setup and 0 hold violations. Logic 61%, BSRAM 66%.

Not checked: make sim mounts no disk, so it does not cover the floppy. Nothing has been on a board.
