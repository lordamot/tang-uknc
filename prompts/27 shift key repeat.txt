****

Fixed in the MCU firmware. It builds and the fix is verified against the real ROM in an emulator; it has not been on the board.

What was wrong, three things stacked:

- The PC ' key was mapped to scan code 05. That is the numeric keypad's comma, not Э (0155, per UKNCBTL's layout). The comma came from the mapping; Shift had nothing to do with the character.
- The real keyboard is a scanned matrix and the ROM counts rows, not keys. One press is reported per row, one release (0200 | row) when the row is empty, and autorepeat runs until releases balance presses. Shift (0105) and the keypad share row 5. The MCU forwarded every USB event, so Shift+' was two presses in row 5, and hid.v truncates a release to its row, so both releases were 0205.
- xm2-01.v latches a key byte only when it differs from the last one, so the second 0205 vanished. Two presses, one release: the ROM repeated the comma until another Shift press and release evened the count.

Evidence, replayed against the real ROM at an RT-11 prompt. The headless UKNCBTL in ../mc0511-dicewars got one extra script command in a private scratchpad copy that pokes R177702 the way the FPGA does. Five seconds after each stream:

  0105 005 0205            the board's stream         a line of commas, and on
  0105 005 0205 0205       with the lost release      one comma, then stop
  Shift + keypad comma     through the real matrix    nothing typed
  0105 025 0205            Shift + PC minus           a line of slashes, and on
  0105 0155 0215 0205      fixed stream, Shift+Э      same as the real matrix
  0105 0175 0215 0205      fixed stream, Shift+-      =

So Shift with the minus key had the same defect, and the fix had to be general.

The fix, mnano/usb_host.c and mnano/uknc.h:

- kbd_tx_uknc() keeps the matrix: which HID keys it has forwarded and how many are down per row, and sends only a row's first press and last release. A press the OSD ate or a MISS key is not tracked, so its release is dropped instead of announcing a row the core never saw; a release of a forwarded key goes out even under the OSD. Two Shifts held are two keys in row 5. Other cores are untouched.
- ' is now 0155 (Э). PC minus moved from the keypad minus (025, row 5) to the machine's - = key (0175, row 13), so Shift+- gives = instead of nothing. Right Alt was 0172 (ПОМ) with a comment saying ГРАФ; it is 066 now.
- The firmware's own function was compiled on the host around a stub to generate the streams above, so the emulator ran the code that ships.

No FPGA change. make fw is clean; the result is in build/fw/bl616.bin and copied over bin/bl616.bin. Flash with make flash-mcu COMX=/dev/ttyACM0, board in boot mode. Nothing committed.

Notes: build/moutst.dsk is not in this repo's build/, so the RT-11 prompt came from mc0511test/toolchain/rt11.dsk with АР2 out of the player it autostarts. Docs updated: mcu.md (a keyboard-rows section and how to test a stream), the CLAUDE.md keyboard trap, progress.md defect 15.

Left open: xm2-01.v has no ready handshake. Two bytes from one USB report (Shift and a letter pressed within the same 8 ms) arrive microseconds apart and the second overwrites the first before the PPU reads it, where the real controller holds the next code back. A one-deep pending register there would close it, but it needs a bitstream, so it is a build of its own.

Backspace, two findings from the emulator with moutst.dsk:

- Its startup does SET TT NOSCOPE, and in that mode RT-11 echoes a rubout as a backslash and the deleted characters instead of erasing them. That is what the emulator shows for Backspace typed through UKNCBTL's own matrix, so the printing itself is RT-11's hardcopy echo, not the keyboard. SET TT SCOPE at the prompt gives the erasing behaviour back.
- Backspace shares row 10 with A, K, M and 3. The faithful matrix rule from the last fix swallows the next key down in a held row, so a Backspace rolled in from A before A was up never arrived. The filter now sends rollover inside a row as a release of the row and a new press, and forgets the row's older keys. Two Shifts are one code held twice.

Verified at the real ROM's RT-11 prompt with the shipped function generating the bytes: A then Backspace rolled in either order, K rolled into A, both Shifts either order then 1 giving !, Shift+' and Shift+-, keys released under the OSD - all as expected. Shift with a keypad key now types the keypad key instead of nothing.
